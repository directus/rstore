# 0.8 to 0.9 Migration Guide

Collaboration features (clocks, last-writer-wins merge, tombstones, text merge, presence and the multiplayer protocol) moved out of `@rstore/core`, `@rstore/shared` and `@rstore/vue` into the new [`@rstore/multiplayer`](../data/collaboration.md) package. None of them was in a tagged release, so this only concerns nightly (`pkg.pr.new`) users. The old names keep working during 0.9 where it is possible, and are removed in 0.10.

## Codemod

The codemod rewrites imports and cache options in `.ts` files (Vue SFC script blocks are not scanned). Download [`multiplayer-0.9.yml`](https://github.com/Akryum/rstore/blob/main/scripts/codemods/multiplayer-0.9.yml), then run:

```sh
pnpm dlx @ast-grep/cli scan -r multiplayer-0.9.yml --update-all src
```

Then run your formatter (for example `eslint --fix`): moved names get one import statement each.

| Before | After |
| --- | --- |
| HLC, LWW, text and tombstone helpers from `@rstore/core` | `@rstore/multiplayer/clock`, `/lww`, `/text` |
| LWW, text and protocol types from `@rstore/shared` | `@rstore/multiplayer` |
| Protocol guards (`parseMultiplayerMessage`…) from `@rstore/shared` | `@rstore/multiplayer/protocol` |
| `writeItem({ fieldTimestamps })`, `deleteItem({ deletedAt })`, `applyMutation({ … })` | `metadata: { fieldTimestamps }`, `metadata: { deletedAt }` |
| `createStore({ tombstoneGc })` | Removed, with a `TODO` comment: pass it to `createMultiplayerPlugin({ tombstoneGc })` |
| `conflict.localTimestamp` / `remoteTimestamp` | Reported only |

## Install the multiplayer plugin

    nuxt: true,

/>

::: info Why this change?
The cache no longer has a built-in merge policy. Field-level last-writer-wins, tombstones and their GC timer are a plugin, built on generic cache extension points, so stores that never receive stamped data pay nothing for them.
:::

Without `createMultiplayerPlugin()`:

- stamped writes (`metadata.fieldTimestamps`) overwrite the cached row instead of merging field by field;
- deletes with `deletedAt` record no tombstone, so stale frames can resurrect deleted rows;
- no tombstone GC timer runs.

In development, the cache warns about the unhandled `fieldTimestamps`/`deletedAt` metadata.

```ts
import { createMultiplayerPlugin } from '@rstore/multiplayer' // [!code ++]

const store = await createStore({
  schema,
  plugins: [
    remotePlugin,
    createMultiplayerPlugin(), // [!code ++]
  ],
  tombstoneGc: { intervalMs: 30_000 }, // [!code --]
})
```

`createMultiplayerPlugin({ tombstoneGc })` takes the former store option. [Nuxt + Drizzle](../../plugins/nuxt-drizzle.md#concurrent-edits) installs the plugin automatically when `ws` is enabled (`ws.lww: false` opts out).

## Form `$rebase` text merge

<FrameworkBadges
  :frameworks="{
    vue: true,
    nuxt: true,
  }"
/>

Without a [`formFieldMerge`](../plugin/hooks.md#formfieldmerge) handler, a field changed both locally and remotely is a conflict, even when the text edits do not overlap. The multiplayer plugin registers the text merger (`formTextMerge`, on by default); standalone forms take `createFormObject({ fieldMerge: textFieldMerger })`.

`$conflicts` entries are `FormFieldConflict { field, localValue, remoteValue }`: `localTimestamp` and `remoteTimestamp` are removed (they were always `Date.now()`).

## Cache API

<FrameworkBadges
  :frameworks="{
    vue: true,
    nuxt: true,
  }"
/>

| Before | After |
| --- | --- |
| `cache.writeItem({ fieldTimestamps })` | `cache.writeItem({ metadata: { fieldTimestamps } })` |
| `cache.deleteItem({ deletedAt })` | `cache.deleteItem({ metadata: { deletedAt } })` |
| `fieldTimestamps` / `deletedAt` mutation options | `metadata` |
| `cache.readFieldTimestamps` / `writeFieldTimestamps` | `getFieldTimestamps(store, …)` / `setFieldTimestamps(store, …)` |
| `cache.tombstones` / `gcTombstones` | `getTombstone(store, …)`, `tombstoneEntries(store)`, `gcTombstones(store, olderThan)` |

The old forms still work in 0.9 and warn once in development. Custom `Cache` implementations must implement [`itemMetadata`](../data/cache.md#item-metadata) and call the `cacheBeforeWriteItem` / `cacheBeforeDeleteItem` hooks.

## Hook typing

`cacheConflict` is declared by `@rstore/multiplayer`: `hook('cacheConflict', …)` only type-checks when the package is installed. See [Conflicts](../data/collaboration.md#conflicts).

## SSR state

`getState()` returns `itemMetadata` instead of `fieldTimestamps` and `tombstones`. Hydration in the same build needs no change; code reading the payload directly must update.

## Nuxt multiplayer packages

  :frameworks="{
    vue: false,
    nuxt: true,
  }"
/>

- `@rstore/nuxt-multiplayer` composables keep their names. Their logic is `createPresenceChannel` from `@rstore/multiplayer/presence`. Deep imports of `runtime/utils/*` break: `validateMultiplayerMessage` is replaced by `parseMultiplayerMessage(raw, { onInvalid })` from `@rstore/multiplayer/protocol`, and the cursor helpers moved to `@rstore/multiplayer/presence`.
- `channel.clearFocus(field)` ignores a delayed blur of a field that no longer has the focus.
- `@rstore/nuxt-multiplayer-server` keeps its module options and `rstoreMultiplayerServerHooks`. `Room`, `RoomRegistry`, `PeerIdentityStore`, `PeerRateLimiter` and `isOriginAllowed` come from `@rstore/multiplayer/server`.
